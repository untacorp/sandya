# Frontend Architect Skill

This skill guides the agent in transforming high-level **User Flows**, UX wireframes, and business specifications into **industrial-grade Frontend Architecture Plans**. It ensures frontend codebases are modular, performant, accessible, type-safe, and resilient to offline/network disruptions.

---

## 🎯 Core Architectural Principles

Every frontend plan generated by this skill adheres to these enterprise engineering standards:

1. **Strict Server vs Client Component Boundaries (React 19 / RSC)**:
   - Maximize React Server Components (RSC) for data fetching, static rendering, and initial HTML delivery.
   - Push `'use client'` down to the smallest possible leaf nodes (interactive forms, modals, scanner canvases, optimistic buttons).
2. **Feature-Sliced / Modular Organization**:
   - Organize code by domain features (`src/features/<feature>/...`) containing colocated `components/`, `hooks/`, `api/`, `types/`, and `schemas/`.
   - Shared atomic primitives live in `src/shared/ui/` (built on Tailwind CSS v4 & accessible Radix primitives).
3. **Multi-Layered State Management**:
   - **Server State / Cache**: TanStack Query (React Query) with explicit query key factories and cache invalidation rules.
   - **Client Global State**: Zustand stores with scoped selectors to prevent unnecessary re-renders.
   - **Local-First & Offline State**: Embedded SQLite / IndexedDB with optimistic mutation queues and rollback support.
   - **URL State**: Search params for shareable filters, pagination, and tabs (`nuqs` / `useSearchParams`).
4. **Universal 6-State UI Matrix**:
   - Every screen, modal, and data card MUST explicitly define 6 UI states:
     1. `Initial Loading` (Skeleton layout without CLS layout shift).
     2. `Empty State` (Illustration + contextual call-to-action button).
     3. `Populated / Success` (Data rendered with full accessibility attributes).
     4. `Error State` (Human-readable message + inline Retry button + Error Boundary).
     5. `Offline / Syncing State` (Persistent indicator + optimistic badges).
     6. `Conflict Resolution State` (Side-by-side comparison modal).
5. **Type-Safe Forms with Zod Colocation**:
   - React Hook Form paired with Zod schemas shared directly with domain validation models.
6. **Hardware & Native Bridge Integration**:
   - Clear contract definitions for desktop/mobile hardware bridges (Tauri v2 `@tauri-apps/api`, Barcode Scanner plugin, Native Notifications, Camera streams).

## 📋 Detailed Phase Breakdown

### Phase 1: Route & Layout Architecture
- Map the user flow's steps into Next.js App Router structures:
  - Root Layout (`src/app/layout.tsx`)
  - Sub-layouts (`src/app/(dashboard)/layout.tsx`, `src/app/(pos)/[posId]/layout.tsx`)
  - Route Groups `(auth)`, `(app)` to isolate layout styling
  - Parallel & Intercepting routes for modals (`@modal/(.)scanner`)

### Phase 2: Server vs Client Component Tree
- Identify which components run on the server (fetching from database/API) and which run on client:
  ```
  [Server] PosDashboardPage
    ├── [Server] PosHeaderBanner (Static metadata)
    ├── [Server] EvacueeStatsGrid (Aggregated counts)
    └── [Client] EvacueeFilterableTable (Search, filter, pagination)
          ├── [Client] EvacueeRow (Optimistic item)
          └── [Client] OpenScannerButton (Triggers native camera)
  ```

### Phase 3: Component Hierarchy & Props Contracts
- Define TypeScript interfaces for props, events, and slots.
- Standardize UI primitives with `class-variance-authority` (CVA).

> Consult [Component Architecture Guide](./references/component-architecture.md).

### Phase 4: State & Data Fetching Architecture
- Design query key factories: `const evacueeKeys = { all: ['evacuees'] as const, list: (posId: string) => [...evacueeKeys.all, 'list', posId] }`.
- Design optimistic mutations with cache snapshot and rollback (`onMutate`, `onError`, `onSettled`).

> Consult [State & Data Fetching Guide](./references/state-and-data-fetching.md).

### Phase 5: 6-State UI Matrix Formulation
- Tabulate and specify every view across:
  - Skeleton loading (matching exact dimensions to prevent CLS).
  - Empty state with clear guidance.
  - Error recovery boundary.
  - Offline badge and conflict alert modal.

> Consult [UI State Matrix Guide](./references/ui-state-matrix-guide.md).

### Phase 6: Output & Delivery
Format the final specification using the [Frontend Plan Template](./references/frontend-plan-template.md) and save it in `docs/frontend/<feature-name>-plan.md` or present it as a planning artifact.
